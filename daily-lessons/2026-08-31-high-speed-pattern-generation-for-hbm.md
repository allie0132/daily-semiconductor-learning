# High-Speed Pattern Generation for HBM

*Monday, Aug 31 2026*

*Module 16.5 — HBM Test Program Development & Characterization*

## Why Pattern Selection Matters in HBM Testing

HBM operates at data rates from 2.4 Gbps (HBM2) to 9.6+ Gbps (HBM3E) per pin. At these speeds, the pattern driven on the DQ/DQS bus directly determines which inter-symbol interference (ISI), crosstalk, and supply-noise conditions are excited. A pattern optimised for **worst-case signal integrity** catches margin failures that a simple checkerboard or all-ones burst will miss entirely.
The ATE channel's internal pattern memory, pattern generator (PG) hardware, and the HBM PHY's built-in LFSR-based PRBS engine must be co-ordinated. JEDEC JESD235C §8 specifies the self-test modes (MBIST, per-lane LFSR) that the HBM die exposes; the tester drives the control commands while the die generates or checks its own patterns.


## PRBS Fundamentals and JEDEC-Mandated Sequences

A **Pseudo-Random Binary Sequence (PRBS)** is generated by a Linear Feedback Shift Register (LFSR). The degree of the polynomial sets the sequence length: PRBS-7 = 2^7−1 = 127 bits; PRBS-31 = 2^31−1 ≈ 2.1 billion bits.
- **PRBS-7** — short, fits entirely in ATE deep-memory at high speed; used for quick lane-level eye-margin sweeps.- **PRBS-23** — standard for HBM SerDes-style characterisation; long enough to stress burst-error correctors (ECC) in HBM3.- **PRBS-31** — used for thorough retention screening and DRAM data-retention tests where the long period prevents any single cell from seeing a repetitive pattern.JEDEC JESD235C Table 14 mandates a PRBS-7 seed of `0x7F` for PHY self-test modes; mismatches between tester and die seed produce false FAIL.


## Algorithmic Patterns: March, Solid, Checker

Where PRBS targets SI, **algorithmic patterns** target cell-interaction faults. The ATE pattern compiler translates a high-level march description into per-DQ burst commands at the HBM command interface.
- **Solid-0 / Solid-1 (SOL)** — all cells written to 0 or 1; screens short/open defects and confirms write-enable path.- **Checkerboard (CB)** — alternating 0/1 per cell on a chess-board address map; maximises worst-case coupling noise between adjacent cells and word lines.- **March C−** — 6-step sequence (`⇕(w0); ⇑(r0,w1); ⇑(r1,w0); ⇓(r0,w1); ⇓(r1,w0); ⇕(r0)`); covers all simple Address Decoder Faults (ADF) and Coupling Faults (CF) in O(n) time. Industry standard for HBM MBIST via JESD235C Mode Register writes.- **March SS** — extends March C− with diagonal address stress; effective against inter-stack coupling in HBM3 4-Hi and 8-Hi stacks.ATE platforms (Advantest T2000, Teradyne UltraFLEX) implement these as built-in algorithms to minimise pattern memory depth requirements.


## Custom Stress Patterns: ISI Hammers, Vcc Droop, and Aggressor Sequences

Production screening increasingly demands patterns tailored to the specific failure modes found during characterisation. Three categories dominate HBM stress pattern libraries:
- **ISI hammer patterns** — long runs of same-polarity bits followed by a single transition (`0000…01`). Forces the worst-case pre-cursor ISI at the DQ receiver. Parameterised by run length (typically 15–31 UI at characterisation, 7 UI at production).- **Supply-noise aggressor (SNA) patterns** — simultaneous switching of all 128 DQ pins in the same direction to induce maximum Vdd/Vss bounce. Used with a VDD parametric sweep to find the dynamic Vmin. JEDEC JESD235C §9.4.2 refers to this as the _all-banks-active worst-case power pattern_.- **Thermal-stress patterns** — sustained read or write at maximum tCK (minimum period) to maximise junction temperature ΔT during burn-in. Pairing with ATE per-pin voltage forcing isolates thermal electromigration risk in the μbump interconnect layer.Custom patterns are typically authored in the ATE's C-like pattern language (`.pat` for Advantest V93000; `STIL` for Teradyne), compiled, and downloaded to the channel FPGAs before the test program runs.


## Integrating Tester-Generated and Die-Internal Patterns

HBM3/HBM3E PHYs include a **Built-In Self-Test (BIST)** engine per pseudo-channel that runs PRBS-7 or PRBS-23 internally, requiring only clock and command stimulus from the tester. The tester must:
- Issue `MRS` writes to Mode Register 4 (MR4) bits [3:0] to select BIST mode and PRBS seed (JESD235C Table MR4).- Toggle `BIST_ACTIVATE` via a direct-command sequence on the CA bus.- Poll the `ALERT_n` pin or read DQ lane status via MR readback to retrieve pass/fail per lane.The tester's own PRBS generator can run in parallel as a _reference checker_, comparing the die's self-reported error count against the tester's independent eye measurement. Discrepancies between die-reported and tester-measured BER exceeding a 10× factor warrant per-lane PHY trim investigation.
Pattern co-ordination is timing-critical: the BIST start command must be issued within ±2 tCK of the pattern generator arming, or the LFSR seed slips and creates false FAIL. Teradyne UltraFLEX achieves this with hardware-synchronised pattern trigger signals on the HBM interface card.


## Key Takeaways

- PRBS-7/23/31 sequences stress ISI and burst-error correction; use the JEDEC-specified seed (0x7F) to avoid false FAIL with on-die BIST.
- March C− is the O(n) algorithmic standard for MBIST in HBM; March SS adds inter-stack coupling coverage for 4-Hi/8-Hi stacks.
- ISI hammer and supply-noise aggressor patterns target characterisation-discovered failure modes and must be co-authored with PHY bring-up data.

## Additional Learning: PRBS Seed Slip and μbump Defect Correlation

When BIST PRBS-7 seed synchronisation drifts by even one UI — due to μbump resistance mismatch or DLL phase error — the on-die LFSR and tester reference fall out of phase, producing a burst-error pattern indistinguishable from a real lane fault. Cross-correlating the error position map (which die columns and rows report errors) against the known bump-pitch map allows engineers to separate true cell failures from synchronisation artefacts: a synchronisation slip produces errors on all rows of a pseudo-channel simultaneously, whereas a genuine cell fault is row-selective. This technique was formalised in the Samsung HBM2E bring-up whitepaper (2020) and is now embedded in most ATE HBM diagnostic flows.
